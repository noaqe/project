# Демонстрация и подготовка к защите

Это план изучения и показа проекта. Перед защитой самостоятельно пройдите сценарий и убедитесь, что можете объяснить код, SQL и свои изменения.

## Сценарий на 5–7 минут

1. Запустите PostgreSQL и приложение без аргументов. Откройте README и ER-диаграмму. Назовите шесть таблиц, объясните связь книг и авторов M:N.
2. **Книги → Все / Поиск**: найдите `Martin`, покажите автора вместе с книгой. Откройте `JdbcBookDao.search()`: JOIN для загрузки связанных объектов, подзапрос для поиска среди всех соавторов, параметры вместо конкатенации.
3. **Книги → Добавить**: используйте не занятый в demo ISBN `9780134494166` (Clean Architecture), год 2017, категорию Programming и автора Robert C. Martin из справочников, 1 экземпляр. Измените название/число экземпляров, найдите по ID и удалите с `YES`, пока выдач нет. Так показан полный CRUD книги.
4. **Читатели → Добавить**: создайте `Test Reader`, `test.reader@example.com`, тип STUDENT. Найдите по имени/ID, измените имя, удалите. Так показан полный CRUD второй сущности.
5. Создайте другого читателя для выдач. **Выдачи → Выдать**: введите ID существующей книги и читателя. **Книги → Наличие**: свободных экземпляров стало на один меньше. Повторная выдача той же книги этому читателю отклоняется. Верните книгу по ID выдачи, проверьте наличие и историю.
6. **Отчёты → Популярность / Статистика категорий / Просрочки**. Покажите `COUNT`, `GROUP BY`, `LEFT JOIN` в `JdbcReportDao`. В demo есть одна просроченная выдача.
7. Введите буквы вместо пункта меню, неверный email или ISBN. Покажите понятную ошибку и продолжение работы. Откройте UML и объясните наследование, интерфейс, Strategy и разделение слоёв.

Не используйте для CRUD-удаления книги или читателей с историей: такой DELETE намеренно запрещён внешним ключом.

## Вопросы, которые надо уметь разобрать

**Почему JDBC, а не Hibernate?** В курсе требуется понимать SQL и PreparedStatement; JDBC + DAO достаточно для этой программы. DAO отделяет детали хранения от интерфейса пользователя.

**Где наследование?** Абстрактный `Person` хранит общие поля человека. `Reader extends Person` добавляет тип абонемента и переопределяет `getRole()`. Через ссылку `Person` вызывается реализация читателя.

**Где полиморфизм полезен для правил?** `LoanService` работает с `LendingPolicy`. Реализации Student/Guest дают разный срок и лимит, сервис вызывает одинаковые методы интерфейса.

**Почему `Book` не наследует `Author`?** Книга не является автором. Она содержит список ссылок на объекты авторов. Автор существует независимо от книги: это агрегация.

**Что обеспечивают 1NF/2NF/3NF?** Атомарные значения; отсутствие зависимости от части составного ключа; отсутствие транзитивных зависимостей неключевых атрибутов. См. `database.md` с ключами каждой таблицы.

**Почему количество доступных экземпляров не поле?** Его можно вывести из фонда и активных выдач. Если хранить оба значения, их придётся синхронизировать при каждой операции.

**Зачем транзакция при создании книги?** Нужно записать книгу и всех соавторов. Если один ID автора неверен, rollback отменяет всю запись, а не оставляет книгу без связей.

**Могут ли два человека получить последний экземпляр?** Через приложение выдачи блокируют одну и ту же строку книги с `FOR UPDATE`, затем проверяют количество внутри транзакции. Вторая выдача ждёт первую и видит её результат. Аналогично строка читателя защищает его лимит.

**Что такое ACID здесь?** Atomicity - книга и авторы записаны целиком либо никак. Consistency - FK, UNIQUE, CHECK и бизнес-проверки. Isolation - транзакции и блокировки. Durability - PostgreSQL сохраняет подтверждённые изменения.

**Почему `LEFT JOIN` и `COUNT(l.id)`?** В отчёте нужны и книги без выдач. У них `l.id` равен NULL, поэтому COUNT даст ноль. `COUNT(*)` сосчитал бы строку соединения.

**Почему PreparedStatement?** Введённая строка передаётся отдельно как значение параметра, а не становится частью синтаксиса SQL. Процент и подчёркивание дополнительно экранированы для буквального поиска.

**Что такое `record`?** Компактный неизменяемый тип данных Java: поля, конструктор, аксессоры, equals/hashCode/toString. Основные примеры обычных классов и наследования находятся в `Book`, `Person`, `Reader`.

**Почему нельзя удалить вернувшего всё читателя?** Историческая выдача ссылается на него. Физический DELETE нарушил бы историю. В рабочей системе можно добавить признак архивации; здесь сохраняется FK RESTRICT.

## Где поставить breakpoint

- `ConsoleMenu.readBook()` - значения из меню и создание модели.
- `JdbcBookDao.create()` - начало транзакции, вставка книги и списка авторов.
- `LoanService.issue()` - выбор стратегии.
- `JdbcLoanDao.issue()` - блокировки, проверки и INSERT.
- `Database.transaction()` - commit и rollback.
